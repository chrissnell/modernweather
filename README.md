# ModernWeather

Next generation weather server — a Rust rewrite of
[remoteweather](https://github.com/chrissnell/remoteweather).

## Status

Design phase. No implementation code yet.

## Where things are

| Path | Contents |
|---|---|
| `docs/rewrite/` | Agent prompts, one per work item. Start with `docs/rewrite/README.md` |
| `docs/` | Design documents produced by those work items land here |
| `contract/` | The frozen legacy REST surface: `legacy-v1.json`, 70 golden fixtures, and a conformance runner that replays them against any base URL |

`docs/rewrite/README.md` is the entry point: it carries the execution order, the output contract that
makes the work items combinable, the measured facts about the existing system, and an auditable
inventory of every capability that has to be carried forward.

## How the work is organised

Eleven design work items, tracked as a Multica issue tree and sequenced by stage. Each produces a
design document committed here on its own `design/<item>` branch, and each must end with four
sections — Decisions, Open questions, Assumptions about other work items, and Proposed amendments —
so that W6 can reconcile them into a single implementation plan.

```
W0  spike → decisions
     ├── W1   frozen API contract
     ├── W2   metric registry + codegen
     ├── W2a  component + capability model
     └── W8   CI + release
                └── W3  service architecture
                        ├── W4  database schema
                        ├── W5  management UI
                        └── W7  collector
                                 └── W9  data migration
W6  reconciliation + implementation plan
```

## Relationship to remoteweather

`chrissnell/remoteweather` is a **read-only behavioural reference** throughout. It stays deployable
and in production until this replaces it.

Two things carried forward deliberately:

- **The legacy REST contract is frozen.** The iOS app and the existing weather website must keep
  working unchanged; new endpoints are additive only. The surface is captured in
  `docs/legacy-api-contract.md` and defined executably by `contract/`.
- **The public weather website is carried forward as-is**, with one exception:
  `weather-app.js.tmpl` — JavaScript generated by Go's `text/template` — is replaced with static
  JavaScript plus a JSON configuration endpoint.

The dead Go utilities in that repo are **not** carried over.

## Decisions already made

Recorded with rationale in `docs/rewrite/W0-spike-and-decisions.md`, which becomes `docs/DESIGN.md`:

- Rust and tokio
- storage stays a **wide** table, not narrow/EAV — Postgres stores a NULL as one bit, and narrow
  measured 7–9× worse on density with no crossover
- raw data retained **indefinitely** with compression, which makes continuous aggregates disposable
  and is what makes adding a metric cheap
- aggregates are hierarchical and store **composable** state, never a finished average
- **one metric registry in TOML** generates DDL, migrations, aggregate SQL, Rust types, protobuf,
  OpenAPI and TypeScript; identifiers are allocated once and never reused
- schema changes only via migrations — no DDL at startup
- admin auth is a username and password, one administrator, no RBAC
- management UI is **Svelte** on the [`chonky`](https://github.com/chrissnell/chonky) toolkit
- internal vocabulary is not user-facing vocabulary
